# Конфигурация

Привязки задаются в `options.bindings` записи плагина в `cli.json`. Полный пример подключения находится в [README](../README.ru.md#конфигурация).

## Поля привязки

| Поле | Обязательность | Значение |
| --- | --- | --- |
| `id` | Да | Уникальный непустой идентификатор |
| `key` | Да | Непустая строка клавиши или альтернатив |
| `title` | Да | Непустое название в палитре команд |
| `action` | Нет | `command` по умолчанию или `goal-toggle` |
| `command` | Для `command` | Непустое имя серверной команды |
| `text` | Нет, только для `command` | Строка аргументов, по умолчанию `""` |

Пробелы по краям `id`, `key`, `title` и `command` удаляются. В `text` пробелы сохраняются.

Для `goal-toggle` поля `command` и `text` запрещены, даже если они пустые. Неизвестные поля и значения `action` отклоняются. В `options` разрешено только поле `bindings`; его отсутствие или пустой массив не создаёт действий.

Конфигурация проверяется целиком. При ошибке плагин показывает уведомление и не регистрирует ни одной привязки.

## Серверная команда

```json
{
  "id": "resume-goal",
  "key": "ctrl+alt+r",
  "title": "Продолжить цель",
  "command": "goal",
  "text": "resume"
}
```

Отсутствующий `action` равнозначен `"action": "command"`. Имя команды не должно начинаться с `/` или содержать пробельные символы. Аргументы передаются отдельно в `text`.

Этот вариант вызывает серверную команду через `session.command`. Он не запускает произвольные локальные действия интерфейса OpenCode: наличие пункта в палитре само по себе не означает, что его можно указать в `command`.

## Переключение Goal

```json
{
  "id": "goal-toggle",
  "key": "f4",
  "title": "Приостановить / продолжить цель",
  "action": "goal-toggle"
}
```

Плагин читает Goal по фактическому расположению текущей сессии, затем вызывает `goal pause` для активной цели или `goal resume` для приостановленной. При отсутствии или завершении цели действие молча заканчивается. Оно не создаёт Goal и не подставляет новый objective.

Pause меняет состояние Goal и приостанавливает автопродолжение. Session interrupt не вызывается: текущая генерация не останавливается, как при Escape.

Чтение и управление не атомарны: другой клиент может заменить Goal между запросами, а API хоста не предоставляет compare-and-swap.

## Клавиши

В `key` можно перечислить альтернативы через запятую, например `f4,ctrl+alt+g`. Пустые альтернативы и пересечения между привязками или внутри одной привязки запрещены.

При поиске пересечений учитываются регистр, порядок модификаторов и алиасы:

- `enter` / `return`
- `esc` / `escape`
- `pgdown` / `pagedown`, `pgup` / `pageup`
- `control` / `ctrl`
- `alt` / `option` / `meta`

`cmd` и `command` не считаются алиасами. Синтаксис клавиш интерпретирует хост; плагин не проверяет его полную грамматику. Терминал или ОС могут перехватить сочетание раньше OpenCode.

Клавишу определяет `bindings[].key`. Переопределение через `keybinds[id]` не поддерживается; поле сочетания клавиш внизу палитры остаётся пустым.

## Выполнение и ошибки

- Действия доступны в текущей сессии, но не на стартовом экране.
- Горячие клавиши не выполняются поверх диалогов. Выбор из палитры запускает действие после закрытия её диалога и повторной проверки той же сессии.
- Черновик не заменяется и не отправляется.
- Одна привязка в одной сессии не запускается повторно, пока её запрос не завершён. Блокировка общая для клавиатуры и палитры, но не для разных экземпляров плагина или поколений перезагрузки.
- Ошибка вызова показывает общее уведомление без аргументов и текста исходной ошибки; после завершения запроса действие можно повторить.

Для `goal-toggle` молча обрабатываются только точные ошибки `No active goal to pause.` при pause и `No paused goal to resume.` при resume. Они означают, что состояние изменилось между чтением и командой. Другие ошибки, включая некорректный ответ о состоянии Goal, показывают уведомление.
