# Тестирование

## Автоматические проверки

Из корня проекта с Node.js >=22.18.0 и npm:

```sh
npm ci --ignore-scripts
npm run typecheck
npm run build
npm run test:dependencies
npm audit --audit-level=moderate
COMMAND_HOTKEYS_PACK_TEST=1 npm test
node .github/scripts/package-smoke.mjs
```

- `typecheck` проверяет типы без генерации файлов; `build` создаёт `dist`.
- `npm test` проверяет конфигурацию, передачу команд, состояния Goal, выбор сессии, модальные ограничения, повторные вызовы и очистку обработчиков.
- `COMMAND_HOTKEYS_PACK_TEST=1` включает упаковочный тест. Без флага он пропускается.
- `test:dependencies` проверяет consumer-сценарии, граф зависимостей и security-регрессии.
- Полный `npm audit` включает dev-зависимости и завершает проверку ошибкой при уровне moderate или выше.
- `package-smoke.mjs` создаёт tarball, устанавливает его в отдельный consumer с `--ignore-scripts` и импортирует `opencode-command-hotkeys/tui`.

CI выполняет проверки на Linux с Node.js 22.19.0 и 24. Модель хоста в unit-тестах не заменяет проверку терминала и интерфейса.

## Ручные сценарии

Подключите собранный пакет в OpenCode 2.2.5 по [примеру конфигурации](../README.ru.md#конфигурация).

1. Создайте Goal и нажмите F4 при закрытых диалогах. Проверьте переход active → paused, затем paused → active. Пауза не должна рассматриваться как interrupt текущей генерации.
2. Повторите действие без Goal и с завершённой Goal. Новая цель и уведомление об ошибке не должны появляться.
3. Введите многострочный черновик и добавьте вложение. Вызовите действие; убедитесь, что черновик и вложение остались на месте и не были отправлены.
4. Откройте диалог вопроса или разрешения и нажмите F4. Команда не должна выполняться.
5. Выберите действие в палитре. Оно должно выполниться после закрытия диалога палитры в той же сессии.
6. Переключите сессию во время чтения Goal. Управляющая команда не должна уйти в новую сессию.
7. Быстро повторите одну клавишу при незавершённом запросе. Повторный вызов той же привязки должен быть подавлен; после завершения клавиша снова работает.
8. Задайте неверную серверную команду. Проверьте уведомление без аргументов и возможность повторного вызова после ошибки.

Отдельно проверяйте изменение CLI-конфигурации и замену кода пакета: изменение или удаление привязки не должно оставлять старые обработчики. Проверьте конфликты с сочетаниями терминала и другими плагинами.
